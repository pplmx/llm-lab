# 卡片量到了什么

界面里除了七个阶段的原始数值，还配了八张「多问了一步」的卡片。它们回答的是几个
光靠「打开界面看一眼」答不了的结构问题，比如「四个头真的在分工吗」。

下面每一条的数都是**从当前权重现算出来的**，卡片本身也这样算：把测试里写的数字改掉，
界面上的字不会跟着变；把代码算的东西改掉，测试会失败（`internal/app/readme_cards_test.go`
解析本文件的数字，与卡片用的同一份计算比对）。

返回 [README](../README.md)。

## 为什么第 5 步多了一张「每一层会说什么」

那张卡是 **logit lens**：网络只在最后一层做一次 LayerNorm 与投影，把这两个提前套用到中间某一层，就能读出「如果模型停在这里，它会说什么」。**它不是模型真的算过的东西**，中间那些答案没被训练过，也不参与输出。放它进来是因为它最能说明「中间层很确定」并不等于「它知道最终答案」：

- 默认提示词、最后一个位置：输入向量与层 0 注意力后的答案都是 `"d"`，到层 0 FFN 后变成 `"␣"` 并给出 100%，层 1 注意力后回落到 62.6%，最终 93.0%（这两个是 T = 1.00 的值；卡片按读者当前温度画，默认打开的 T = 0.80 下是 66.6% 与 97.0%）——**真正让预测出现的是 FFN，注意力单独不改变答案**
- 把整句提示词的每一层都读一遍：**180 个中间层里有 92 个的答案与最终答案不同**，其中 **76 个对自己的错误答案有 90% 以上的把握**（T = 1.00；默认温度下是 77 个，因为有一个刚好落在 90% 这条线上）。**36 个位置里每一个**都至少有一层如此
- 图表画的是「这一层给最终答案多少概率」，不是 top-1 概率、也不是熵。后两者都试过，那张图没有信息：这个模型中间层的分布几乎是 one-hot（熵 0.00，对着 ln 256 = 5.55 的天花板），所有条都是一根细丝

最后一格是**该位置**的真实输出：`Trace.Logits` 只存最后一行（`Forward` 只投影那一个位置），所以位置不是末尾时要用 `Unembed(FinalNorm[pos])` 现算——那一行已经过了最终 LayerNorm，因此直接 `Unembed`，不能再调 `LogitLens`（会归一化两次，实测 256 个 logit 全部不同）。`TestLogitLensFinalRungIsTheOutputAtThatPosition` 逐个位置核对，`TestLogitLensAgreesWithThePerPositionCard` 则要求它与第 7 步的逐位置卡片**说出同一个字节**——这两条正是发现上面那个 bug 的测试。

## 权重绑定让预测变成一个余弦

第 7 步一直说输出矩阵「就是嵌入矩阵本身」（权重绑定），但没说这件事对预测意味着什么。答案是可以精确写出来的：字节 b 的 logit 恰好是它与最终向量的内积，而内积能拆成三个量相乘。默认提示词最后一个位置，模型选中的那个字节：

**logit 25.770 = ‖E[b]‖ 9.973 × ‖x‖ 9.351 × cos 0.2763**

三者相乘与 logit 逐位一致。真正决定名次的是哪个量？

| 量 | 256 个字节上的范围 | 与 logit 的相关 |
| --- | --- | --- |
| ‖E[b]‖ | 8.29 – 11.71 | **−0.000** |
| cos(E[b], x) | −0.324 – +0.276 | **+0.997** |

所以在这个模型里，「模型喜欢哪个字节」等于「哪个字节的输入嵌入与输出方向更同向」——不是比喻，就是这套算术。按 logit 排与按 cos 排不一样的字节对只有 **563 / 32640（1.7%）**。

绑定不是免费的：它省了 2.4 万个参数，同时把输入空间和输出空间焊在一起，这是一个结构选择。

## 学出来的位置编码和 sin/cos 长得完全不一样

第 2 步说位置向量是学出来的，但没说学成了什么样。实测（默认权重）：

| | cos(P[t], P[t+1]) | cos(P[t], P[t+32]) |
| --- | --- | --- |
| 这个模型学出来的 | **+0.040** | **−0.052** |
| 经典固定正弦编码 | +0.969 | +0.562 |
| 96 维里两个随机向量 | ≈0.102（期望） | |

也就是说：**学出来的位置表把 64 个位置放成了 64 个几乎互不相干的地址**，相邻余弦只有 0.040，比随机向量还小；而经典正弦编码是沿一条平滑曲线每次走一小步（0.969）。两种都能用——正弦编码让「近」在几何上有意义，学出来的表让模型自己决定哪个方向代表哪个位置——**而这个仓库的架构并没有规定哪一种，是梯度下降选了这个**。

这张卡有一个「常见误解」：「位置编码就是那套 sin/cos 公式，所有 transformer 都这样」。

三处容易看漏的细节：

- **头是分开算的**：`HeadProj[h]` 是 `Out_h · Wo[h*d_head:(h+1)*d_head]`，`AttnProj` 就是各头之和，所以第 4 步卡片里「本头贡献」和「全部头相加」是两个不同的量。
- **`-Inf` 是掩码，不是数值**：`Scores` 右上角是 `negInf`，`softmaxCausal` 直接在 `i+1` 处截断，从不真的对它做指数。
- **`Logits` 只有一行，但预测不只有一次**：`FinalNorm` 是 `T × d_model`，`Trace.Logits` 只保存**最后一个位置**的那一行，宽度是词表大小——本模型把 96 维的向量点乘到 `TokEmbed` 的 256 行上，得到 256 个 logit（形状 `[T, 96] → [1, 256]`），所以第 7 步顶上那张卡片看的是「最后一个 token 之后的那个字」。但**每个位置都能预测**，而且前面 T−1 个位置的预测还有答案可核对：提示词里就写着真实的下一字节。第 7 步的「每个位置都在预测」卡片用 `Weights.Unembed` 把每一行投影一遍，逐位置比对，给出猜对率与平均交叉熵（本权重实测 24/35；平均损失随温度变化，默认打开的 T = 0.80 下是 **1.184 nats**、T = 1.00 下是 1.121，两者都对着均匀猜测的 ln 256 = 5.545）。`Unembed` 与 `Forward` 用同一个 float32 累加顺序，所以最后一行的结果与 `Trace.Logits` **逐位相同**，由 `TestUnembedReproducesTheRecordedLogits` 钉住。

每次 `Forward` 会把每个中间张量录进 `model.Trace`（`gpt.go`），界面只读这份缓存——所以拖动滑块、切换层/头都不需要重算整个网络。

## 四个头真的在分工吗

第 4 步那张「四个头各自在做什么」把这个问题变成两个可以读的量：**每一行给紧邻前一个 token 的平均权重**，以及**有多少行把一半以上权重压在同一个 key 上**。默认提示词、整句 35 行平均，实测：

| 层 | H0 | H1 | H2 | H3 | 判断 |
| --- | --- | --- | --- | --- | --- |
| 0 | 66% | 22% | 37% | 61% | 差别明显（跨度 44 个百分点） |
| 1 | 13% | 14% | 14% | 12% | 看不出分工（跨度 3 个百分点） |

所以「每个头学到不同的模式」在第 0 层成立、在第 1 层不成立。卡片会随层把结论写出来，不会让读者自己去找一个不存在的差别。这一点检查器那张「这一行的统计」看不出来——两个头可以在同一行上有完全相同的熵，却在看不同的地方。

## 四个头说的是同一件事吗

第 4 步的「加权求和」卡片画出「每个头各写了多少」，然后「全部头相加」。但为什么是**拼接**四个切片再投影，而不是先相加？因为四个头说的不是同一件事——这个可以量：

| 层 | 两两投影输出的平均余弦（最小–最大） | 各头占 ‖Δ‖ 总量 |
| --- | --- | --- |
| 0 | **+0.027 – +0.144** | 19% – 32% |
| 1 | +0.098 – +0.537 | 21% – 28% |

层 0 的四个头几乎互不相干，量级又相当；先相加再投影会让这些差别互相抵消。所以「多几个头」不是求平均求稳，而是**并行的四条通道**。层 1 的头之间重合得多一些，这和「前一层广泛改写、后一层做窄修正」是同一件事的两面。

## 掩码到底挡掉了什么

第 3 步还有一张「掩码挡掉了什么」：它用模型自己存下来的 `Q`/`K`，把选中那一行**不看掩码**地重算一遍。掩码之上的分数在 `HeadTrace.Scores` 里是 `-Inf`，所以要按同样的 `1/√d_head` 与同样的 float32 点积顺序重算，得到的才是被掩码删掉的那些数、而不是一组看起来差不多的近似值。

这个反事实不是小幅变化。默认提示词、整句平均，**每个头都会把 51%–84% 的注意力放到被掩码遮住的位置上**；第 0 行最极端——它只有一个可见 key，去掉掩码后 **100%** 的注意力跑到后面，其中最大的一格是 k34 的 47%。也就是说因果掩码不是「顺手加的安全带」，而是这道题唯一的难度来源：没有它，模型第一步就会去读后面还没写出来的内容。

卡片还并列两个熵：模型实算的那一行（只看得到 q+1 个 key）与去掉掩码后的那一行（看得到全部 T 个）。两者差多少，就是掩码在这一行上省下的选择空间。

## 嵌入向量里有「意思」吗

第 2 步每条色带的每一格是一个维度，很自然会想：意思相近的字节，向量是不是也靠得近？这个问题可以量——把 256 个字节的嵌入两两算余弦，看「文本里挨着出现的字节」是不是比随便两个更像。实测（默认提示词）：

| | 平均余弦 |
| --- | --- |
| 文本里相邻的 35 对 | **+0.0213** |
| 随便两组（32640 对） | +0.0033（标准差 0.1017） |
| 元音之间 / 元音与辅音之间 | +0.0335 / 0.0000 |

**两者差别落在噪声里。** 最像的 20 对字节里只有 1 对两边都是可读字符，排第一的是 `I` 和一个控制字节 `\x9a`。

原因不神秘：这个模型的嵌入表是在 61 句话上训练的，96 个维度够它记住「哪些字节常见」，不够长出语义几何。真实的大模型里这种结构确实存在——但那是几十亿 token 训出来的，不是「嵌入」这个结构本身自带的。

> 量的时候要排除同一个字节重复的情况（`attention` 里的 `tt`、`all` 里的 `ll`）：同一个字节和自己的余弦恒为 1，会把这个平均值抬满。卡片上写明了排除了几对。

## FFN 写出了答案

第 6 步那张「FFN 写出了答案」把 FFN 的输出和下一个字节直接对上：把 256 个字节按「它的输入嵌入和这个向量的余弦」排名，看真实的下一个字节排第几（随机是约第 128 名）。实测：

| | 输入里的名次 | FFN 之后的名次 | FFN 之后进前 10 的位置 |
| --- | --- | --- | --- |
| 层 0 | **103.4** | **4.5** | 30 / 35 |
| 层 1 | 3.7 | 10.7 | 20 / 35 |

层 0 的输入里，答案和瞎猜差不多（第 103 名）；经过这一层的 FFN，它排到第 5 名。**也就是说这一步是从无到有地把答案方向写进残差流，而不是修饰一个已有的信号。**

这也正是第 5 步 logit lens 那张阶梯看到的现象（预测在层 0 的 FFN 之后才成形）的机制。层 1 的输入已经在第 4 名，它的 FFN 没有再改善——还是「前一层广泛改写、后一层做窄修正」。

## FFN 的单元也不是平均出力

第 6 步还有一张「单元是怎么分工的」。上面的色带只画了选中位置的 384 个单元；把整句每个位置都算进来，看两个数：多少个单元才凑够一半的激活量，以及有没有单元在每个位置都开着。实测：

| | 凑够一半激活需要 | 每位置都开 | 从不打开 |
| --- | --- | --- | --- |
| 层 0 | **130 / 384** | **0** | 0 |
| 层 1 | **28 / 384** | **17** | 27 |

层 0 要把一百多个单元摊开才凑够一半，而且**没有任何单元在整句每个位置都开着**——它按位置调动不同的单元；层 1 只用 28 个就够，其中 17 个从头开到尾。这个模式在三个提示词上都成立（层 0 需 118–130 个，层 1 需 28–35 个）。

这和「每一层改写了多少」说的是同一件事的两面：**前一层广泛改写，后一层做窄而重复的修正**。

## 两层做的活不一样多

第 5 步还有一张「每一层改写了多少」。它可以切换层，每张图都会重画，但从没说过两层是不是在做同等的劳动。答案是否定的，而且非常稳定：

| 提示词 | 层 0 进出余弦 | 层 0 ‖ΔFFN‖/‖x‖ | 层 1 进出余弦 | 层 1 ‖ΔFFN‖/‖x‖ |
| --- | --- | --- | --- | --- |
| `The transformer reads the tokens and` | 0.23 | 3.17 | 0.93 | 0.43 |
| `attention is all you need` | 0.22 | 3.12 | 0.92 | 0.41 |
| `Attention lets every token…` | 0.24 | 2.78 | 0.92 | 0.45 |

层 0 把残差流的方向改得几乎认不出来（余弦 0.22–0.24），写进去的内容是它读到的 2.8–3.2 倍；层 1 基本保持方向（0.92–0.93），只加了 0.41–0.45。**这个两层模型里大部分变换发生在第一层**，第二层是在磨尖。这与上面 logit lens 的观察是同一件事的两面：预测在层 0 的 FFN 之后就已经成形。

所以「加一层」不等于「把同一件事再做一遍」——每一层的活是训练出来的，各不相同。
